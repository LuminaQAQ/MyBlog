# 007\_包与仓库管理

本章重点为命令.

- `monorepo`: 若同一个项目中, 有一个或多个项目之间相互依赖, 但是不考虑 git 独立性.
- `git submodule` 和 `git subtree`: 若同一个项目中, 有一个或多个项目之间相互依赖, 需要考虑 git 独立性.

## monorepo

初始化

```shell
npm init -w packages/core -y
npm init -w packages/cli -y
```

在某个 workspace 下安装依赖：

```shell
npm install core --workspace cli
```

在某些包下执行命令：

```shell
npm exec --workspace @lumina-npm/cli -- npx tsc --init
```

在全部包下执行命令

```shell
npm exec --workspaces -- npx tsc --init
```

## git 管理

`git submodule` 和 `git subtree`. 简单来说, `submodule` 更偏向 "独立仓库", `subtree` 更偏向 "仓库合并".

`git submodule` 管理的子项目, clone 后需要单独拉取被引用的子项目, 而 `git subtree` 能够直接将子项目拉取下来.

### git submodule

添加子模块：

```shell
git submodule add <url> <path>
```

clone 主仓库后, 子模块目录是空的, 需要单独拉取：

```shell
git submodule init
git submodule update
# 或者一步到位
git submodule update --init --recursive
```

clone 时直接带上子模块：

```shell
git clone --recurse-submodules <url>
```

拉取子仓库的远程更新：

```shell
git submodule update --remote <path>
```

在子模块目录内可以像普通仓库一样切分支、提交、推送, 主仓库通过 commit 指针记录子模块当前的版本.

删除子模块：

```shell
git submodule deinit -f <path>
git rm -f <path>
rm -rf .git/modules/<path>
```

### git subtree

添加子仓库（`--squash` 表示不拉取子仓库的历史记录, 只保留一条合并提交）：

```shell
git subtree add --prefix=<path> <url> <branch> --squash
```

拉取子仓库的更新：

```shell
git subtree pull --prefix=<path> <url> <branch> --squash
```

把 `<path>` 目录下的改动拆出来推回子仓库：

```shell
git subtree push --prefix=<path> <url> <branch>
```
